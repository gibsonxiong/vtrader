# 浏览器助手

这个 skill 用于在当前环境已有工具的基础上处理浏览器相关任务。

## 何时触发

当出现以下情况时触发本 skill：

- 用户要求打开或检查本地前端预览页
- 用户反馈浏览器控制台错误或网络请求错误
- 用户希望抓取某个 URL 的页面内容
- 用户希望快速排查正在运行的 Web 应用问题
- 用户要求搜索与前端问题相关的网页资料

## 这个 Skill 做什么

- 在开发服务器可用时打开本地预览地址
- 抓取用户提供的网页内容
- 将浏览器可见错误与相关前端代码进行关联分析
- 在必要时搜索框架相关错误资料
- 协助区分问题来自预览环境、前端构建、后端接口还是鉴权流程

## 工作规则

1. 如果本地开发服务器已经运行且有可用预览地址，优先打开预览页面。
2. 如果用户提供了 URL 并希望分析页面内容或结构，先抓取网页内容。
3. 如果用户反馈浏览器错误，需要结合请求路径、页面路由和相关前端源码一起排查。
4. 如果问题依赖实时文档或框架当前行为，需要进行网页搜索。
5. 需要明确指出问题更可能来自前端代码、接口行为、路由、鉴权还是环境配置。

## 能力边界

- 除非环境里确实提供了浏览器自动化工具，否则不要声称自己可以点击、输入或交互式操作页面。
- 不要声称能够检查当前工具实际拿不到的运行时 DOM 状态。
- 不要虚构控制台输出、网络请求详情或截图内容。
- 如果任务确实需要浏览器自动化，要明确说明当前环境能力不足。

## 典型流程

1. 先判断目标是本地预览页面还是公网 URL。
2. 打开预览页面或抓取目标网页内容。
3. 检查相关前端代码和运行时配置。
4. 将错误回溯到请求、路由、静态资源或鉴权流程。
5. 总结发现，并给出最小且有用的下一步建议。

## 使用示例

- “打开前端预览并排查为什么页面是空白的。”
- “分析这个来自本地应用的浏览器控制台错误。”
- “抓取这个 URL 并总结页面内容。”
- “帮我判断这个问题是 Vite、Vue Router 还是后端 API 引起的。”
