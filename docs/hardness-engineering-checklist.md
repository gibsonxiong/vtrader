# Hardness Engineering Checklist

## 认证与权限

- [ ] 统一未授权语义，确保 HTTP `401` 与业务未授权错误进入同一恢复流程
- [ ] 明确 access token 与 refresh token 的生命周期和失效策略
- [ ] 为登录、刷新 token、登出补充失败日志
- [ ] 为菜单、权限码、用户信息拉取增加异常兜底与可诊断提示

## API 与环境

- [ ] 将 Mock / Backend / Trade API / WebSocket 地址统一收口到运行时配置
- [ ] 去除业务代码中的硬编码地址
- [ ] 启动时输出当前生效的 API / WS / Mock 目标
- [ ] 为不同开发模式提供显式环境文件

## WebSocket

- [ ] 为 `/ws` 连接增加身份校验
- [ ] 为订阅消息增加参数校验
- [ ] 限制单连接最大订阅数
- [ ] 增加重复订阅保护
- [ ] 增加频率限制与错误码约定

## 回测与高成本任务

- [ ] 为回测参数设置上限（时间跨度、标的数量、参数规模）
- [ ] 为回测任务增加幂等控制
- [ ] 防止短时间重复提交同类任务
- [ ] 限制队列长度、并发和任务超时时间
- [ ] 支持任务取消、过期或失败恢复

## 输入校验

- [ ] 为后端控制器补齐 DTO 和 validation pipe
- [ ] 为批量接口限制分页、条数和时间范围
- [ ] 统一错误响应结构
- [ ] 为前端表单增加边界值校验与显式错误提示

## 健康检查与可观测性

- [ ] 新增 Redis / DB / Queue 健康检查接口
- [ ] 为关键请求注入 request id / trace id
- [ ] 为回测任务生成统一 job id 并贯穿日志
- [ ] 为认证失败、批量任务、WebSocket 订阅增加结构化日志

## 前端防误操作

- [ ] 为批量下载、删除、回测启动增加二次确认
- [ ] 长耗时任务展示进度、状态和取消入口
- [ ] 对危险操作增加明确文案和颜色区分
- [ ] 对空数据、依赖异常、登录过期提供清晰恢复指引

## 交付验收

- [ ] 新成员可在 10 分钟内完成本地环境判断与联调
- [ ] 所有未授权场景均可自动进入统一恢复流程
- [ ] 回测与批量下载不会因误操作无上限消耗资源
- [ ] WebSocket 连接和订阅具备基础防滥用能力
- [ ] 关键依赖故障时可以在 5 分钟内定位问题点
